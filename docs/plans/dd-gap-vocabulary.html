§1 — Why this release exists

imas-codex composes a standard name for every DD quantity. After its full DD run, 86 sources could not be named because the grammar has no word for something they measure: a power convertor, a slit, a stress tensor, the tritium decay that seeds runaway electrons. imas-codex classified every missing token as add, reject (an existing spelling already says it) or decompose (existing tokens already compose it). That worklist is /home/ITER/mcintos/Code/imas-codex/docs/evidence/fragments/sn-integrity-backlog/sib-vocab-worklist.json, merged in imas-codex 5137eaf7d and read against this repository's tag v0.10.1.

The lead ruled on it on 2026-11-09:

  • Composites are split into their parts. The coil equipment is poloidal_field_coil, never a "circuit". Power equipment is power_convertor, never a "power supply".
  • The clean physics additions are accepted as listed, and so are ten of the eleven rejections. The eleventh, which reused shattered_pellet_species for a pellet species, is carved out into the rework below.
  • The argmax operator and the threshold_crossing state are accepted now, with the grammar machinery they need.
  • Six doubtful additions are reworked once more before any of them enters the grammar: species (subject), breakdown_candidate_grid_point, breakdown_candidate_field_line, current_alignment, plateau and green_function.

This repository owns the vocabulary and its release; imas-codex owns the pin bump, the graph grammar snapshot and the rerun of the sources, under its own plan sn-integrity-backlog §51.

§2 — The accepted vocabulary enters the grammar

Add these 34 tokens, in the segment and vocabulary file the worklist row names and with its one-sentence definition, by editing the vocabulary YAMLs and grammar/specification.yml and regenerating with build-grammar. Never hand-edit the generated files.

horizontal (component), pipe, ion_source, optical_fibre, power_convertor, slit, thermal_shield (equipment objects), image_surface, magnetic_field_line, pre_sawtooth_crash, threshold_crossing (positions), arc_of_circle, oblique, thick_line (geometry representations), image, grid (geometric bases, in geometry_carriers.yml, the vocabulary the worklist rows name; not the geometry segment's positions), ballooning_parameter, delta_prime, stress (physical bases), helical, ripple, sine, cosine, chemical, bounce, compressive, second_inclination, rotational, tangency (qualifiers), tritium_decay, fragmentation, sublimation (processes), lithium_6 (subject), side (zone).

The six equipment objects are entries of the loci: mapping in locus_registry.yml with type: entity, beside antenna_strap and coil_conductor; no new top-level section is added. specification.yml keeps the prefix device segment for parse compatibility only, so every representative name uses the postfix locus form that compose tooling enforces, for example voltage_of_power_convertor, never power_convertor_voltage.

The 34 tokens enlarge the public grammar by design: each becomes a generated enum member and a filter token, and adding the vocabulary the DD needs is this plan's purpose. Nothing is retired in exchange, because every token serves DD sources that cannot otherwise be named.

  • no rejected spelling enters the vocabulary, by explicit membership tests in the grammar suite: fit_offset and s0 to s3 are not qualifiers, outside_last_closed_flux_surface is not a region, and poloidal_field_circuit and poloidal_field_power_supply are not loci; the tokens the worklist reuses keep exactly the registrations they hold today, asserted by name: spun as a qualifier, toroidal as a component and a coordinate axis, coordinate as a geometric base.   • the grammar test suite adds no failure id against the stated base.

§3 — The doubtful additions are reworked

The lead judged six proposed tokens too generic or too composite, and a seventh, source as a qualifier, collides with the physical base source that the grammar's uniqueness test forbids in a second segment. Each is reworked against the DD documentation of the sources that need it.

  • species serves pellets/time_slice/pellet/species/density, an intact pellet. The vocabulary's only pellet species subject is shattered_pellet_species, which names a different DD quantity and must not be reused for it. The rework states whether an intact-pellet species subject is a genuine new token and, if so, its spelling and definition.
  • The two breakdown_candidate_* words are split into their parts.
  • source served edge_sources/source/ggd/current, a source contribution to current density in A.m^-2; the rework expresses it with existing tokens, without a second registration of source.
  • Each of current_alignment, plateau and green_function is expressed with existing tokens or as one named physical quantity whose definition stands on its own.

It waits for §2 so that its spellings are probed against the grammar they will be released into.

§5 — A name can locate the maximum of a profile

argmax is the one accepted addition that is grammar machinery rather than a word. It returns the coordinate at which its operand profile is maximal, so the quantity it names has the dimension of that coordinate, not of the operand. It is declared in operators.yml as the indexed unary-prefix token argmax_with_respect_to, exactly as derivative_with_respect_to is, because the renderer and parser emit the operand-first form only for a token containing _with_respect_to_. Its index parameter is the coordinate, so the name carries the coordinate in the same canonical order, operand first and coordinate last: argmax_of_deposited_power_with_respect_to_normalized_toroidal_flux_coordinate is dimensionless, whatever the unit of power. The indexed-operator machinery and its round-trip tests already exist for the derivative.

A name carries no unit itself; a catalog entry pairs a name with a unit, and validation/semantic.py checks that pairing. An operator's effect on dimension already has one owner, the dimension_transforming field of the operator definition in operators.yml and grammar/vocab_loaders.py, read today only by _load_dimension_transforming_operators() to exempt such operators from the base-implies-unit warning. Rather than add a second field beside it, that field becomes typed: it states what the result's dimension follows, operand for the operators that carry true today and index for argmax_with_respect_to, whose result takes its index coordinate's dimension. No OperatorSemanticEffect member is added. The check reuses what validation/semantic.py already owns: the sibling-entry unit comparison in _check_source_flux_unit_collision is generalised into a named-pair unit check, and the absent-target report of _check_referential_integrity covers a coordinate with no catalog entry. Both return issue strings in the existing families, so an unchecked pairing is an issue a caller sees, never an empty list that reads as a pass.

Done when:

  • dimension_transforming is typed, every operator that carried true carries operand with its existing exemption unchanged by test, and argmax_with_respect_to carries index; run_semantic_checks returns no issue for an argmax entry whose unit matches its coordinate's entry, an issue naming both units for one that carries the operand's unit, and an absent-target issue when the coordinate has no entry, each by test on an entries map;
  • argmax_of_deposited_power_with_respect_to_normalized_toroidal_flux_coordinate, the spelling for the worklist's power-deposition peak, parses with the coordinate as the operator's index parameter, renders canonically and round-trips, by test, and a planted removal of the effect fails its test;
  • the grammar test suite adds no failure id against the stated base.
