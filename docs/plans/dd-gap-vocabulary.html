§1 — Why this release exists

imas-codex composes a standard name for every DD quantity. After its full DD run, 86 sources could not be named because the grammar has no word for something they measure: a power convertor, a slit, a stress tensor, the tritium decay that seeds runaway electrons. imas-codex classified every missing token as add, reject (an existing spelling already says it) or decompose (existing tokens already compose it). That worklist is /home/ITER/mcintos/Code/imas-codex/docs/evidence/fragments/sn-integrity-backlog/sib-vocab-worklist.json, merged in imas-codex 5137eaf7d and read against this repository's tag v0.10.1.

The lead ruled on it on 2026-11-09:

  • Composites are split into their parts. The coil equipment is poloidal_field_coil, never a "circuit". Power equipment is power_convertor, never a "power supply".
  • The clean physics additions are accepted as listed, and so are ten of the eleven rejections. The eleventh, which reused shattered_pellet_species for a pellet species, is carved out into the rework below.
  • The argmax operator and the threshold_crossing state are accepted now, with the grammar machinery they need.
  • Six doubtful additions are reworked once more before any of them enters the grammar: species (subject), breakdown_candidate_grid_point, breakdown_candidate_field_line, current_alignment, plateau and green_function.

This repository owns the vocabulary and its release; imas-codex owns the pin bump, the graph grammar snapshot and the rerun of the sources, under its own plan sn-integrity-backlog §51.

§5 — A name can locate the maximum of a profile

argmax is the one accepted addition that is grammar machinery rather than a word. It returns the coordinate at which its operand profile is maximal, so the quantity it names has the dimension of that coordinate, not of the operand. Like derivative_with_respect_to, it is an indexed unary-prefix operator whose index parameter is the coordinate, so the name carries the coordinate: argmax_with_respect_to_normalized_toroidal_flux_coordinate_of_deposited_power is dimensionless, whatever the unit of power. The indexed-operator machinery and its round-trip tests already exist for the derivative.

A name carries no unit itself; a catalog entry pairs a name with a unit, and validation/semantic.py checks that pairing. Today an operator's dimension_transforming flag in operators.yml is read only by _load_dimension_transforming_operators() in that module, to exempt such operators from the base-implies-unit warning, and nothing derives a dimension from it. No vocabulary file states a unit either. The coordinate an argmax ranges over is its index parameter and is itself a standard name, so its dimension comes from that coordinate's own catalog entry. The check compares the argmax entry's unit with the coordinate entry's unit, and reports an unknown, never a pass, when the catalog holds no entry for the coordinate. The effect is declared in operators.yml and enumerated by OperatorSemanticEffect in the hand-written grammar/vocab_loaders.py.

Done when:

  • argmax carries a named semantic effect stating that the result takes its coordinate's dimension, and validation/semantic.py accepts an argmax entry whose unit matches its coordinate's catalog entry, reports one that carries the operand's unit, and reports an unknown when the coordinate has no catalog entry, each by test against a catalog fixture;
  • argmax_with_respect_to_normalized_toroidal_flux_coordinate_of_deposited_power, the spelling for the worklist's power-deposition peak, parses with the coordinate as the operator's index parameter, renders canonically and round-trips, by test, and a planted removal of the effect fails its test;
  • the grammar test suite adds no failure id against the stated base.
