§1 — Why this release exists

imas-codex composes a standard name for every DD quantity. After its full DD run, 86 sources could not be named because the grammar has no word for something they measure: a power convertor, a slit, a stress tensor, the tritium decay that seeds runaway electrons. imas-codex classified every missing token as add, reject (an existing spelling already says it) or decompose (existing tokens already compose it). That worklist is /home/ITER/mcintos/Code/imas-codex/docs/evidence/fragments/sn-integrity-backlog/sib-vocab-worklist.json, merged in imas-codex 5137eaf7d and read against this repository's tag v0.10.1.

The lead ruled on it on 2026-11-09:

  • Composites are split into their parts. The coil equipment is poloidal_field_coil, never a "circuit". Power equipment is power_convertor, never a "power supply".
  • The clean physics additions are accepted as listed, and so are all eleven rejections. One of them reuses shattered_pellet_species for spi/injector/pellet/core/species/density, which is a shattered pellet, so the reuse is correct; only the intact-pellet path pellets/time_slice/pellet/species/density is reworked below.
  • The argmax operator and the threshold_crossing state are accepted now, with the grammar machinery they need.
  • Six doubtful additions are reworked once more before any of them enters the grammar: species (subject), breakdown_candidate_grid_point, breakdown_candidate_field_line, current_alignment, plateau and green_function.

This repository owns the vocabulary and its release; imas-codex owns the pin bump, the graph grammar snapshot and the rerun of the sources, under its own plan sn-integrity-backlog §51.

§5 — A name can locate the maximum of a profile

argmax is the one accepted addition that is grammar machinery rather than a word. It returns the coordinate at which its operand profile is maximal, so the quantity it names has the dimension of that coordinate, not of the operand. It is declared in operators.yml as the indexed unary-prefix token argmax_with_respect_to, exactly as derivative_with_respect_to is, because the renderer and parser emit the operand-first form only for a token containing _with_respect_to_. Its index parameter is the coordinate, so the name carries the coordinate in the same canonical order, operand first and coordinate last: argmax_of_deposited_power_with_respect_to_normalized_toroidal_flux_coordinate is dimensionless, whatever the unit of power. The indexed-operator machinery and its round-trip tests already exist for the derivative.

A name carries no unit itself; a catalog entry pairs a name with a unit, and validation/semantic.py checks that pairing. An operator's effect on dimension already has one owner, the dimension_transforming field of the operator definition in operators.yml and grammar/vocab_loaders.py, read today only by _load_dimension_transforming_operators() to exempt such operators from the base-implies-unit warning. Rather than add a second field beside it, that field becomes typed: it states what the result's dimension is derived from, operand for the operators that carry true today (whose results transform the operand's dimension, as square, inverse or time_derivative do, rather than equal it) and index for argmax_with_respect_to, whose result takes its index coordinate's dimension. No OperatorSemanticEffect member is added. The check reuses what validation/semantic.py already owns: the sibling-entry unit comparison in _check_source_flux_unit_collision is generalised into a named-pair unit check that compares the argmax entry's unit with its coordinate's entry. An indexed operator's coordinate is fused into its token (the parser yields op='argmax_with_respect_to_<coordinate>' with no arguments), so the check extracts the coordinate by splitting the token on _with_respect_to_, as render.py does, and reports a coordinate with no catalog entry itself, in the same issue family _check_referential_integrity uses for an absent target. Both return issue strings in the existing families, so an unchecked pairing is an issue a caller sees, never an empty list that reads as a pass.

Done when:

  • dimension_transforming is typed, every operator that carried true carries operand with its existing exemption unchanged by test, and argmax_with_respect_to carries index; run_semantic_checks returns no issue for an argmax entry whose unit matches its coordinate's entry, an issue naming both units for one that carries the operand's unit, and an absent-target issue when the coordinate has no entry, each by test on an entries map;
  • argmax_of_deposited_power_with_respect_to_normalized_toroidal_flux_coordinate, the spelling for the worklist's power-deposition peak, parses with the coordinate as the operator's index parameter, renders canonically and round-trips, by test, and a planted removal of the effect fails its test;
  • the grammar test suite adds no failure id against the stated base.
